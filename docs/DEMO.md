# ProjectPilot — Demo Guide

> This guide describes the recommended demo walkthrough, demo credentials, and key talking points
> for judges, examiners, and demonstration audiences.

> **Product framing:** ProjectPilot is an intelligent capstone team formation, role assignment, task
> allocation, and conflict detection platform — with neurodivergent-first support built in as a private
> layer. This demo focuses on the operational foundation and the student support experience that exist
> today; the intelligent formation engine is the planned next module (see
> [`MENTOR_REQUIREMENT_MAPPING.md`](MENTOR_REQUIREMENT_MAPPING.md)). When demoing the **Coordinator**
> account, highlight the formation-readiness signals: unassigned students, team setup gaps, supervisor
> capacity, and team health.

## Recommended Demo Walkthrough (15 minutes)

### Act 1: The Student Experience — Getting Unstuck (5 min)

**Login as Ruvan (student)**

1. **Overview page** — Show the confidence panel ("You've already completed N tasks") and the
   next-best-action card. Note: this is derived from real task state, not a static message.

2. **Support Tools → Low-Energy Mode** — Demonstrate the gentle one-step view. Say:
   > "When a student is overwhelmed, this strips away all noise and shows exactly one small action.
   > The rationale explains why this task was chosen."

3. **Support Tools → Focus Mode** — Click into the recommended task. Show:
   - Task decomposition steps with progress
   - Definition of done
   - Suggested session length from cognitive profile
   - Support prompt adapted to task priority

4. **Support Tools → Communication Tools**
   - Paste: *"I want to check something. The scope section — I'm not sure if it's quite there yet.
     Going forward, maybe consider making it more specific, hopefully by next week if possible."*
   - Use **Social Signal Decoder** — show detected signals: implied criticism, soft deadline,
     vague expectation
   - Use **Communication Style Translator** to rewrite the student's draft response in
     Supervisor-Ready style

### Act 2: Post-Meeting Recovery (3 min)

5. **Consultations** — Navigate to the completed past consultation (Team Vertex, completed meeting).
   Show the **Meeting Recovery Mode** section at the top:
   - Gentle re-entry message
   - Top 3 actions from the meeting
   - What can wait
   - Time-sensitive items
   - Link to Low-Energy Mode

6. Scroll down to show the full **Translated Feedback** section:
   - Action items with priority, owner, and "what done looks like"
   - Hidden assumptions surfaced
   - Things to clarify at next meeting
   - Raw supervisor notes collapsed

### Act 3: Team Intelligence (4 min)

**Login as Dr. Perera (supervisor)**

7. **Team Insights** — Show the full intelligence dashboard:
   - Health signals with reason text (not just red/yellow/green)
   - Ambiguity summary — tasks missing definition of done
   - Workload distribution bars — show if one member carries more
   - Dependency and blocker risks
   - Coordination burden visibility
   - Recommended actions with urgency ranking

**Switch back to Ruvan (student)**

8. **Team Insights (student view)** — Show the filtered student view:
   - Shared health signals (team-level only, no per-member comparisons)
   - Task clarity analysis for their own tasks
   - Top recommendations

### Act 4: The Architecture Story (3 min)

9. Briefly show the Project Brain:
   - Decision log with rationale
   - Open questions with priority
   - Feedback memory from the supervisor

10. Show the Supervisor workspace (as Dr. Perera):
    - Pre-meeting brief generation
    - Team member profiles
    - Consultation readiness indicator

## Key Demo Talking Points

**On intelligence without LLM:**
> "Every signal you see was generated by a deterministic rule-based system. You can click on any
> health signal and read exactly why it was flagged. That explainability was a deliberate design
> choice — students and supervisors need to be able to trust what they see."

**On privacy:**
> "The cognitive support features — focus mode, low-energy mode, communication tools — these outputs
> never leave the student's session. The supervisor cannot see whether a student used Low-Energy Mode.
> Support data is private by architecture, not just by policy."

**On the communication translator:**
> "This is pattern-based text transformation. It's deterministic and readable. In Phase 2, the same
> typed interface connects to an LLM — the UI doesn't change, only the backend implementation."

**On the meeting recovery:**
> "This feature was specifically designed for the documented reality that intense meetings are
> cognitively overwhelming for many neurodivergent students. After a supervision meeting, the system
> shows you the 3 things that matter most, what can wait, and the one gentlest possible first step.
> That's not fluff — it's occupational therapy applied to software."

## Common Questions from Judges

**"Is this production-ready?"**
> The codebase is production-grade in architecture and security patterns. A Docker image can be
> deployed to AWS App Runner with a single command. The full deployment guide is in `docs/DEPLOYMENT.md`.

**"How many users can it support?"**
> The stateless Next.js architecture horizontal-scales on App Runner. The database (PostgreSQL on RDS)
> scales vertically and can add read replicas for analytics queries. For a university deployment, this
> comfortably handles 500–2,000 concurrent users on a `db.t3.small` + App Runner configuration.

**"What happens if the AI signals are wrong?"**
> Every signal has a reason text. Users can see why it was triggered. The system never takes action
> on behalf of a user — it surfaces information for human decision-making. A false positive is a
> slightly unnecessary notification, not a harmful action.
